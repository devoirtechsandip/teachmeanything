Branches as Lightweight Movable Pointers

Demystify Git branching: discover why Git branches are practically free, how HEAD tracks where you are, and why git switch replaces the confusing legacy git checkout.

1 The Truth About Git Branches: It's Just a 41-Byte File!

In older version control systems, creating a "branch" meant copying an entire 500MB directory across the disk. It was slow and wasteful.

In Git, a branch is simply a text file containing 40 hex characters and a newline stored in .git/refs/heads/. It is literally a pointer to a specific commit. Creating a branch takes 1 millisecond and consumes 41 bytes!

2 Meet HEAD: "You Are Here"

If a repository has 5 branches, how does Git know which branch you are actively working on? Through a special pointer called HEAD.

🎯 The Pointer Hierarchy

Normally, HEAD points to a branch name (e.g. HEAD -> main), and the branch name points to a commit hash (e.g. main -> c1a4). When you make a commit, the active branch pointer moves forward automatically with you!

3 Modern CLI: "git switch" vs "git checkout"

✨ Modern Verbs (Git 2.23+)

  • git switch feature-login — Switch branches
  • git switch -c feature-cart — Create & switch in one command
  • git restore app.js — Discard file edits (clean separation!)

🕰️ Legacy Overloaded Verb

  • git checkout feature-login — Switched branches
  • git checkout -b feature-cart — Created & switched
  • git checkout -- app.js — Discarded files

Note: git checkout did too many unrelated jobs. Use modern git switch today!
