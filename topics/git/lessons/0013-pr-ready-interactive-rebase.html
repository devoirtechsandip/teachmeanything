Lesson 0013 • Module 6 ⏱️ 8 min read 🛠️ Interactive Squash Editor

PR-Ready Interactive Rebase (git rebase -i)

Transform messy local hacking into clean Pull Requests: learn how to squash typo fixes, reword sloppy commit messages, and safely push with --force-with-lease.

1 The Anatomy of a Messy Branch

When developing locally, your commit log often looks like this:

* 91a4b12 fix typo in variable name
* 5c2190f oops forgot semicolons
* 120fb34 wip button styling
* 8a21390 feat: add checkout payment modal

Submitting this as a Pull Request will frustrate code reviewers. With Interactive Rebase, you can condense those 4 messy commits into 1 perfect, atomic commit before anyone else sees it.

2 The Interactive Command Verbs

pick

Keep the commit as-is.

reword

Keep the code changes, but open editor to write a better commit message.

fixup

Meld this commit into previous commit and discard its commit message (ideal for typo fixes!).

squash

Meld this commit into previous commit and combine both commit messages.

3 Safe Remote Publication: --force-with-lease

🛡️ Never Use Bare --force

If you previously pushed your feature branch to GitHub and then rebased it locally, standard git push will be rejected. Never run git push --force (it can destroy teammate commits if they pushed to your branch!).
Always use git push --force-with-lease: it verifies nobody else updated the remote before updating it.
