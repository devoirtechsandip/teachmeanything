Under the Hood: The Git Object Store

The capstone of your Git journey: look directly into .git/objects/, understand the 4 immutable primitives (blobs, trees, commits, tags), and master Git plumbing commands.

1 Git is a Content-Addressed Key-Value Store

Beneath the polished CLI commands (add, commit, checkout), Git is fundamentally an astonishingly simple, elegant key-value database:

🔑 Key-Value Architecture

Key: The 40-character SHA-1 hash of the compressed data.
Value: The compressed binary data stored at .git/objects/ab/12345....

2 The 4 Core Git Objects

1. Blobs (Binary Large Objects)

Pure raw file data. Blobs contain no filenames, directory paths, or timestamps. If 10 files in your repository have the exact same content, Git stores only 1 blob!

2. Trees (Directories)

Represents a directory folder. A tree object maps human-friendly filenames and file permissions to blob hashes or child subtree hashes.

3. Commits (Snapshots)

A 200-byte text metadata file pointing to:

  • The root Tree SHA of the project
  • Parent commit SHA(s)
  • Author and committer identity
  • Commit message

4. Annotated Tags

A permanent reference pointer tied to a specific commit with release notes and GPG signatures.

3 The Swiss Army Knife: git cat-file

The official plumbing command to inspect raw Git objects is git cat-file:

# Check object type: blob, tree, or commit
$ git cat-file -t e4a19b2
commit

# Pretty-print contents of an object
$ git cat-file -p e4a19b2
tree 9a8c14f5...
parent 3d21b01a...
author Sandip Kumbhar <sandip@example.com> 1730590000 +0530
committer Sandip Kumbhar <sandip@example.com> 1730590000 +0530

5 Knowledge Check

Does a Git blob object store the filename or file permissions?
A) Yes, all file metadata is stored in the blob header.
B) No. Blobs only store raw file contents. Filenames and permissions are stored in Tree objects.
C) Only on Linux file systems.
