Fast-Forward vs Three-Way Merges

Understand how Git integrates divergent histories: why some merges create new commits while others simply slide a pointer forward.

1 Scenario A: The Fast-Forward Merge

Imagine you created a branch feat/cart from commit C1 on main. You made two commits (C2 and C3). Meanwhile, nobody made any commits on main.

⚡ Fast-Forward Mechanism

Because there are no diverging commits on main, Git doesn't need to combine anything. When you run git switch main && git merge feat/cart, Git simply moves the main pointer forward to point to C3. No extra merge commit is created!

2 Scenario B: The Three-Way (Recursive/ORT) Merge

Now imagine that while you were working on feat/cart, your teammate merged commit C4 into main.

Now both branches have moved in different directions starting from their common ancestor (C1, the merge base). Git cannot simply slide a pointer forward. Instead, Git inspects:

  1. Commit C1 (Merge Base): The last shared snapshot.
  2. Commit C3 (Feature Tip): Your additions.
  3. Commit C4 (Main Tip): Teammate's additions.

Git synthesizes all changes into a brand-new commit called a Merge Commit (M1), which uniquely possesses two parents!
