Inspecting History, Diffs & Commit Hygiene

Master the tools professional developers use every single day: visualizing project history with git log, inspecting exact line differences with git diff, writing atomic commits, and ignoring build junk with .gitignore.

1 Seeing What Actually Changed: Why "git status" Isn't Enough

In Lesson 0002, you learned that git status tells you which files were modified or staged. But it does not tell you what lines changed inside those files.

Imagine you edited 50 lines in auth.js. Before staging, you must answer: Did I leave a debug console.log? Did I accidentally paste an API secret? This is where git diff is your magnifying glass.

2 The Two Diffs: Working Tree vs Staging Area

git diff (Unstaged)

Compares your Working Tree against your Staging Area. Shows you edits you have saved to disk but have not yet staged with git add.

diff --git a/app.js b/app.js @@ -1,3 +1,4 @@ const port = 3000; -const mode = 'development'; +const mode = 'production'; +console.log('Server starting...');

git diff --staged

Compares your Staging Area against your Last Commit (HEAD). Shows you exactly what will go into the next snapshot if you run git commit right now.

diff --git a/app.js b/app.js @@ -1,2 +1,3 @@ const port = 3000; +const dbUrl = process.env.DB_URL; server.listen(port);

4 Keeping Your History Clean: The .gitignore File

Never commit temporary build artifacts, compiled binaries, dependency directories, or sensitive passwords. The special file named .gitignore tells Git to silently ignore them.

nano .gitignore
# Dependencies
node_modules/
vendor/

# Environment secrets
.env
*.pem

# Build output
dist/
build/
*.log

5 The Art of the Atomic Commit

💡 The Golden Rule of Commit Hygiene

An atomic commit does one thing and one thing only. It makes code review easy, keeps Git history readable, and allows clean rollbacks if a bug emerges.

Use the standard Conventional Commits format:

feat(auth): add token refresh endpoint
fix(cart): prevent negative item quantity on checkout
docs(readme): add local docker setup instructions
