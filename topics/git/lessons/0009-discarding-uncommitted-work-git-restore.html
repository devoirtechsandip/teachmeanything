Discarding Uncommitted Work with git restore

Take control of your local edits: learn how modern git restore elegantly unstages changes from the index and rolls back botched file experiments in your working tree.

1 The Two Uncommitted Disasters

Every developer encounters two daily scenarios before committing:

Scenario 1: "Oops, I Staged the Wrong File!"

You accidentally ran git add .env or staged an incomplete file. You don't want to lose your edits; you simply want to remove it from the staging area.

$ git restore --staged .env

✓ Moves .env out of the Staging Area back to unstaged Working Tree. Your code is 100% safe!

Scenario 2: "Throw Away My Terrible Edits!"

You spent 30 minutes hacking on widget.js, broke everything, and want to throw it in the trash and restore the clean version from your last commit.

$ git restore widget.js

⚠️ Permanent discard: Replaces your working file with the pristine version from the Staging Area / HEAD!
