Team Synchronization: fetch, pull & push

Master the distributed heartbeat: learn why git pull is really two commands under the hood, how git fetch lets you inspect changes safely, and how to resolve rejected pushes.

1 The Fundamental Formula: pull = fetch + merge

The single most important equation in Git remote networking is:

⚡ The Core Sync Formula
git pull  =  git fetch  +  git merge

1. git fetch (Safe Look)

Downloads all new commits, objects, and branches from the remote, and updates your origin/main bookmark. It touches zero working files on your disk. You can run fetch without fear of broken code or conflicts.

2. git pull (Fetch + Combine)

Runs git fetch to download commits, and immediately runs git merge into your active local branch. If changes clash, you may enter a merge conflict instantly.

2 The "Rejected Push" Panic Explained

You run git push origin main and see this dreaded terminal wall:

! [rejected] main -> main (fetch first)
error: failed to push some refs to 'https://github.com/org/repo.git'
hint: Updates were rejected because the remote contains work that you do
hint: not have locally. This is usually caused by another repository pushing...

What this means: A teammate pushed commits before you. Git protects you: it will never allow you to silently overwrite their work! You must pull/fetch their changes first, integrate them, and then push.

B) No. It only downloads objects and updates remote tracking references like origin/main.
C) Only if you run it as root.
