Quick Reference Card #02

The Three Areas & The Staging Workflow

A fast-reference guide for navigating the Working Tree, Index/Staging Area, and Git Commit History.

1. The File Lifecycle in Git

Untracked
➔ git add ➔
Staged
➔ git commit ➔
Committed
➔ edit file ➔
Modified

2. Understanding the Three Areas

Area Underlying Path Role in Workflow
Working Tree Your local folder files The files you see and edit in your IDE. Where experimental, uncommitted work lives.
Staging Area (Index) .git/index The staging buffer. Holds the exact files and versions prepared to join the next snapshot.
Git Repository .git/objects/ The permanent, content-addressed database of sealed commits and tree graphs.

3. Staging & Committing CLI Commands

Command Effect & Best Practice
git status Shows uncommitted files categorized by untracked (red), modified (red), or staged (green).
git status -s Compact two-column status output (?? = untracked, M = staged, M = unstaged).
git add <file> Stages an individual file. Best practice: use explicit file paths for focused, atomic commits.
git add . Stages all changes in the current directory and subdirectories.
git restore --staged <file> Un-stages a file, moving it back from Staging Area to Working Tree without losing any code.
git commit -m "message" Records the staged snapshot permanently with a clear descriptive message.
git commit -v Opens your terminal editor showing the exact diff of what you are committing.
