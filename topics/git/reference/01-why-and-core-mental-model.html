Git Foundations & Core Mental Model

A compressed cheat sheet of the fundamental reasons for version control, Git's snapshot mechanics, and essential Day 1 terminal commands.

1 The "Why": What Git Solves

1. Time Travel

Instantly jump back to any prior working version of your software without keeping duplicate folders or messy _v2_final files.

2. Zero Overwrite Risk

Multiple developers can work on the exact same files simultaneously. Git isolates individual work and flags overlapping lines cleanly.

3. Complete Accountability

Every single line of code is attributed to an author, a timestamp, and a clear message explaining why the change was introduced.

4. Fearless Experimentation

Create cheap branch sandboxes to test radical ideas. If it fails, delete the branch with zero impact on the working main codebase.

2 The "How": Git's Snapshot Model

Unlike older version control systems (like SVN or CVS) that stored a base file plus lists of line-by-line differences (deltas), Git thinks in snapshots:

  • Every time you commit, Git takes a picture of what all your files look like at that exact moment and stores a reference to that snapshot.
  • To be extremely fast and efficient, if a file has not changed, Git does not store the file again—it simply links directly to the identical file it already stored.
  • Everything in Git is checksummed using cryptographic hashes before it is stored, making it mathematically impossible to alter history undetected.

3 The Three Areas (Mental Map)

Area Location What It Does
Working Directory Your local folder (files you edit in VS Code / terminal) Uncommitted scratchpad where you edit, delete, and experiment with real files.
Staging Area (Index) .git/index binary file The staging preview where you pick and choose exactly what changes go into the next snapshot.
Git Repository .git/objects/ database Permanent history of sealed, immutable commit snapshots.

4 Fundamental Day 1 CLI Commands

Command Description & Use Case
git init Turns the current directory into a tracked Git repository by creating the hidden .git database folder.
git status Your navigation compass: inspects which files are modified, untracked, or staged for the next commit.
git add <file> Moves changes from the Working Directory into the Staging Area (prepares them for the snapshot).
git add . Stages all new, modified, and deleted files in the entire project workspace.
git commit -m "message" Seals staged changes into a permanent snapshot with an informative description.
git log --oneline Displays a compact chronological list of commits in your project history.
